# API

## Реализованные маршруты

### GET /health

`200`: `{"status": "ok"}`. Проверяет только процесс, без БД/DeepSeek.

### GET /v1/products

`200`: объект с `data_status: "demo_unverified"`, `warning` и `products`.
Нет фильтров и пагинации: каталог маленький и демонстрационный.
Пример одной записи:

```json
{
  "id": "oats",
  "name": "Овсяные хлопья",
  "state": "dry",
  "nutrition_per_100g": {
    "calories_kcal": "370", "protein_g": "13", "fat_g": "7", "carbs_g": "62"
  },
  "package_size_g": "500",
  "price": 89.9,
  "price_region": "Москва",
  "price_source": "Демонстрационная оценка, не магазин",
  "price_updated_at": "2026-10-10"
}
```

Состояния: `dry`, `raw`, `cooked`. КБЖУ относятся к указанному состоянию
и 100 г, размер упаковки — граммы. Дата цены — ISO `YYYY-MM-DD`.
Деньги — JSON-числа в рублях, не строки и не копейки; `89.9` равно `89.90`.
Остальные Decimal-поля сериализуются строками штатным Pydantic v2.
Демонстрационные цены и КБЖУ не проверены для реального питания.

### Стандартная документация

`GET /docs`, `GET /redoc`, `GET /openapi.json`. OpenAPI описывает только
работающие маршруты; схема будущего запроса не подключена к endpoint.

## Планируемый контракт генерации — endpoint отсутствует

Python-схема: `meal_budget.schemas.generation.GenerationRequest`.
Путь, статусы задания и контракт результата будут определены позже.
Пример будущего запроса:

```json
{
  "days": 7,
  "budget": 2500.50,
  "daily_targets": {
    "calories_kcal": 2000, "protein_g": 100, "fat_g": 70, "carbs_g": 250
  },
  "excluded_product_ids": ["oats"],
  "disliked_product_ids": [],
  "max_cooking_minutes": 30,
  "meals_per_day": 3,
  "price_region": "Москва",
  "wishes": "Простые блюда"
}
```

- `days`: строго целое 1–31, по умолчанию 7.
- `budget`: положительный конечный Decimal до 1 000 000 рублей на **весь период**,
  максимум два значимых разряда после запятой; принимаются числа и десятичные строки.
- `daily_targets`: ежедневные КБЖУ, каждое поле положительное и конечное,
  максимум 100 000. Это технический предел, не медицинская норма.
- Списки ID: до 500 элементов каждый, по умолчанию пустые. ID длиной 1–64,
  символы `a-z`, `0-9`, `_`, `-`. Проверка существования ID — будущая логика.
- `max_cooking_minutes`: строго целое 1–240, будущий предел на приготовление блюда.
- `meals_per_day`: строго целое 1–10.
- `price_region`: непустая строка до 120 символов.
- `wishes`: до 2000 символов, по умолчанию пустая строка.

Неизвестные поля запрещены. Строки очищаются от пробелов по краям.
Булевы значения не принимаются вместо строго целых полей.
Никакие генерационные маршруты сейчас не зарегистрированы; фиктивного меню нет.
