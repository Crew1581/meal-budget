# Последовательные этапы

Готов только фундамент: health, демонстрационный JSON-каталог, схема запроса,
конфигурация, тесты, Docker и CI. Всё ниже — **планы**, не текущие возможности.

1. **Детерминированное расчётное ядро.** КБЖУ по граммовкам, корзина по целым
   упаковкам, Decimal-стоимость и бюджет; определить округление, проверить
   на маленьких unit-тестах без модели. Уточнить качество исходного каталога.
2. **Проверка меню.** Исключённые/нелюбимые ID, состояние продукта,
   реалистичность порций, целевые КБЖУ и лимит приготовления; проверяемые ошибки.
   Расширить единицы упаковок за пределы граммов, не смешивая массу и объём.
3. **DeepSeek и цикл исправления.** Выбрать доступную модель, структурированный
   ответ из нашего каталога, timeout и лимиты; повторная проверка и ограниченный
   цикл исправления меню. Никогда не доверять стоимости, рассчитанной моделью.
4. **Публичный API заданий.** Фоновые задания, статусы, идемпотентность,
   временное хранение результатов и очистка по TTL. Выбор серверного хранилища.
   Если нужна БД — yoyo-миграции с зависимостями, rollback и тестом чистой БД;
   при PostgreSQL денежные поля NUMERIC с scale 2.
5. **Защита расходов.** Токены установок без пользовательских аккаунтов,
   квоты, rate limit, ограничения параллелизма и стоимости модели,
   безопасные логи и наблюдаемость. До публичного включения генерации.
6. **Flutter-клиент.** Настройки, запросы/статусы, меню и заметки;
   локальная SQLite с отдельными клиентскими миграциями, без регистрации.
   Проверить восстановление после ошибок сети и отсутствие дублирующих расходов.
