# Последовательные этапы

MEAL-1–MEAL-8 слиты в master, последний merge `40d8ad6` (PR #8).
MEAL-9 реализована локально в одноимённой ветке от этого актуального master, без commit/push.
Последний пользовательский ordinary MEAL-7 успешен за один вызов; новых платных
запусков агент не выполнял. Ограничения и проверки — в [STATUS](STATUS.md).

1. **Детерминированное ядро — реализовано.** КБЖУ по граммовкам, целые упаковки,
   остатки и бюджет; финансовые операции Decimal. Оптимизатора нет.
2. **Сервис DeepSeek и CLI — реализованы.** Независимая проверка, одно предложение
   и до двух исправлений, deadline/лимиты, без скрытых сетевых повторов.
   Исторический технический smoke-тест MEAL-3 выполнен пользователем на demo-данных;
   не доказывает качество недельного рациона.
3. **Закрытый HTTP MEAL-3 — реализован и слит.** Выключен по умолчанию,
   отдельный Bearer, один процесс/слот, тело до 64 KiB, root_path-защита.
4. **Каталог и оценка MEAL-4/MEAL-5 — частично.** Реализованы происхождение источников,
   версия, единые JSON-числа, правило воды, отдельные fixtures и автономная сводка.
   Исправления ревью: demo по умолчанию отделено от реального снимка,
   явный сценарий требует проверенной подготовки, пути CLI проверяются совместно.
   В MEAL-5 импортированы 70 SKU, версия `5ka-2026-10-14-observed-v3`;
   цены, география и наличие не подтверждены. По manifest ordinary и weekly готовы
   по ручным witness с допуском ±10%; preferences, quick, tight-budget и impossible
   остаются blocked. Качество реальной генерации еще не оценено.
   Следующие действия: подтверждение цен/географии/упаковок/КБЖУ разрешенным способом,
   подготовка оставшихся анкет, witness и нижней границы impossible;
   отдельно согласованные одиночные платные прогоны и ручная оценка рецептов.
   Не обходить блокировку и не заменять данные поисковыми сниппетами.
5. **Развитие модели каталога.** Ингредиент → товар → предложение магазина;
   шт./мл/весовые единицы и съедобный выход с явными правилами и тестами.
   Пока не создавать лишние сущности и не менять ядро ради охвата категорий.
   Затем продуктовые правила порций/разнообразия, без медицинских обещаний.
6. **Закрытые задания MEAL-8 — реализованы и слиты.** PostgreSQL + psycopg async pool,
   yoyo apply/rollback отдельно от API, bounded-очередь/один worker, общий слот
   со старым endpoint, восстановление queued по версии, interrupted для running,
   TTL и проверенный результат. Это не публичная авторизация Flutter.
    MEAL-9 добавляет отдельные app-маршруты, токены установок без аккаунтов,
    ограниченную TTL идемпотентность, атомарные personal/global UTC-квоты и cap регистрации.
   Переход к нескольким workers/репликам требует другой координации; текущий
   процессный слот нельзя масштабировать просто увеличением workers.
   Каталог пока JSON, отдельные денежные поля при появлении — NUMERIC(scale 2).
   Активная история yoyo только PostgreSQL; происхождение/неизменность SQLite-архива
   не подтверждены без оригинала. Переноса старых данных нет. Compose/PG-интеграция/CI
   service добавлены.
7. **API приложения MEAL-9 — реализовано локально, закрытый пилот.** Отдельный флаг,
    владельцы в PostgreSQL, одноразовая выдача opaque token с хранением только хеша,
    UNIQUE(owner,key), квоты новых принятых jobs, прежний worker/слот и гарантии MEAL-8.
    Проверки/ограничения — STATUS. До публичного запуска: review/CI, внешний контроль
    доступа пилота, rate/connection/time limits, HTTPS/redaction/наблюдаемость,
    политика revoke/rotation/retention установок и дальнейшая abuse-защита.
    Токен не доказывает уникальность человека; это не денежный лимит и не exactly-once.
8. **Flutter — не реализован.** SQLite на телефоне, запросы/меню/заметки без аккаунтов;
    OS secure storage для токена установки, сохранение Idempotency-Key/параметров до POST,
    polling, безопасное восстановление после потери ответа только в пределах TTL;
    отдельные клиентские миграции, восстановление без дублирующих расходов.
