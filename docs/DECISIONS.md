# Принятые решения

1. **Без аккаунтов, данные локально.** Flutter и SQLite на телефоне позволяют
   начать с простого MVP без профилей и облачной синхронизации.
2. **FastAPI и Pydantic v2.** Небольшой сервер, проверяемые контракты и OpenAPI
   для будущего Flutter-клиента. Без микросервисов и пустых абстракций.
3. **Python 3.13, uv и lock-файл.** Совместимо с подходом референса;
   один способ установки и изолированная `.venv`. Точные стабильные версии
   фиксируются в uv.lock; pytest/httpx/Ruff — только dev-группа.
4. **create_app и lifespan.** Тестируемая сборка и явная проверка ресурсов
   при запуске. Из референса также взято разделение HTTP, схем и будущей логики.
5. **Decimal, рубли.** Финансовая арифметика без binary float; JSON-деньги —
   числа, не minor units референса. float только в выходном сериализаторе.
6. **Локальный демонстрационный JSON.** Достаточно для рабочего API без БД;
   явная маркировка непроверенных данных, проверка при запуске.
7. **PostgreSQL пока не нужен.** Выбор серверного хранилища отложен;
   в PostgreSQL деньги будут NUMERIC с двумя знаками после запятой.
8. **Будущие миграции — yoyo.** Явные зависимости, порядок и rollback;
   Alembic не используется, неиспользуемая зависимость yoyo сейчас не добавляется.
   SQLite-миграции Flutter независимы.
9. **DeepSeek только после проверяющего ядра.** Модель предлагает меню,
   сервер проверяет. Ключ только на сервере; пока ни запросов, ни выбранной
   модели, настройки не зависят от OpenCode.
10. **Минимальные Docker и CI.** Контейнер без root/reload/секретов,
    frozen-установка, проверки без ключа. Compose и внешняя инфраструктура не нужны.
