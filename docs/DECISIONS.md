# Принятые решения

1. **Без аккаунтов, данные локально.** Flutter и SQLite на телефоне позволяют
   начать с простого MVP без профилей и облачной синхронизации.
2. **FastAPI и Pydantic v2.** Небольшой сервер, проверяемые контракты и OpenAPI
   для будущего Flutter-клиента. Без микросервисов и пустых абстракций.
3. **Python 3.13, uv и lock-файл.** Совместимо с подходом референса;
   один способ установки и изолированная `.venv`. Точные стабильные версии
   фиксируются в uv.lock; pytest/Ruff — dev-группа, HTTPX — runtime для DeepSeek.
4. **create_app и lifespan.** Тестируемая сборка и явная проверка ресурсов
   при запуске. Из референса также взято разделение HTTP, схем и будущей логики.
5. **Decimal, рубли.** Финансовая арифметика без binary float; JSON-деньги —
   числа, не minor units референса. float только в выходном сериализаторе.
6. **Локальный демонстрационный JSON.** Достаточно для рабочего API без БД;
   явная маркировка непроверенных данных, проверка при запуске.
7. **PostgreSQL для временных заданий MEAL-8.** Каталог пока JSON, телефон —
   будущая SQLite; профилей и таблиц меню на сервере нет. Отдельные денежные
   поля при необходимости будут NUMERIC с двумя знаками после запятой.
8. **Серверные миграции — yoyo.** Явные зависимости, порядок и rollback;
   Alembic не используется; активная история заданий — migrations/postgresql/.
   SQLite-миграции Flutter независимы.
9. **DeepSeek только после проверяющего ядра.** Модель предлагает меню,
   сервер проверяет. После MEAL-1 реализована интеграция только как сервис/CLI;
   ключ только на сервере, модель конфигурируется независимо от OpenCode.
10. **Минимальные Docker и CI.** Контейнер без root/reload/секретов,
    frozen-установка, проверки без ключа. Compose и внешняя инфраструктура не нужны.
11. **Расчет отдельно от генерации.** `POST /v1/menu-calculations` проверяет
    вручную подготовленное меню. Независимое от FastAPI ядро не подбирает меню,
    не исправляет бюджет и не обращается к DeepSeek.
12. **Граммовки на весь рецепт.** Целое `recipe.servings` задает выход порций,
    дробное `meal.servings` — съедаемые порции. Масса соответствует dry/raw/cooked
    каталога; скрытых пересчетов и веса готового блюда нет.
13. **Упаковки после общей агрегации.** Потребность каждого продукта суммируется
    за весь период; затем покупается ceil целых упаковок. Все покупки с нуля,
    включая масло и специи. Запасы, готовые остатки и сроки хранения не учитываются.
    Остаток означает только неиспользованный купленный продукт.
14. **Точность и округление расчета.** Локальный Decimal-контекст — 80 значащих
    цифр; промежуточные значения не quantize. Общий знаменатель целых порций
    (НОК чисел 1–100, не более 41 цифры) сохраняется до вывода и решения об упаковках.
    Это оставляет запас для ограниченных граммовок, порций, сумм и текущего каталога.
    Периодические дроби вычисляются с этой точностью, не округляются до сотых
    на промежуточных шагах. Вывод — два знака, ROUND_HALF_UP; сравнение бюджета
    с точной Decimal-стоимостью до вывода. Числа JSON сериализуются через float
    только на границе; существующий GET каталога не изменен.
15. **MEAL-2 без публичного HTTP endpoint.** Сначала изолированно проверяем DeepSeek
    и расчетную верификацию. Endpoint появится вместе с заданиями, токенами установок,
    идемпотентностью, временным хранением и лимитами расходов; никаких генераций
    по запросам неавторизованных клиентов на этом этапе.
16. **HTTPX напрямую, один клиент на цикл.** Без большого SDK; транспорт подменяется
    в тестах. Явный async context закрывает клиент при успехе/ошибке. Скрытые повторы,
    redirect и доверие proxy-окружению выключены. Выключенный HTTP endpoint не создает
    ненужный клиент; общим клиентом включенного MEAL-3 владеет lifespan.
17. **Модель и thinking — конфигурация.** Официальная документация проверена
    2026-10-11; пример экономичного имени `deepseek-flash` (DeepSeek-V4.1-Flash),
    JSON Output поддерживается. Settings не выбирает модель за оператора.
    Thinking явно disabled (провайдер иначе включает его); enabled использует low,
    omit доступен для другой модели без этого параметра. Тарифы не кодируются.
18. **Отдельный контракт ответа генерации.** Модель дает рецепты, ингредиенты,
    порции, дни, steps и cooking_minutes, без итогов цены/КБЖУ и бюджета.
    Явное преобразование использует исходный бюджет; расчетный API не меняется.
    Только ограниченный JSON-объект, без regex-извлечения из текста, обрезание — ошибка.
19. **КБЖУ: продуктовая политика, не медицинская норма.** Настраиваемые ±10% каждого
    показателя каждого дня на старте; включительные границы по неокругленным данным
    существующего ядра. Никакого автоматического ослабления бюджета, исключений
    и допусков. Нелюбимые продукты — мягкое предупреждение.
20. **Промпт не является границей безопасности.** Системные правила, анкета и
    серверный каталог разделены, wishes — данные; запрещенные продукты заранее
    исключаются. Промпт снижает риск неправильных инструкций, но не заменяет
    серверную проверку. Время проверяется только заявленное; безопасность блюда
    и медицинская полноценность не проверяются.
21. **Ограниченный цикл и расходы.** Одна исходная генерация и два исправления;
    полный recheck каждого плана. Лимиты tokens, времени, байтов и схемы.
    Исправления содержат конкретные нарушения и предыдущий структурированный план
    только до 64 KiB, без растущей истории и сырого невалидного текста.
    Сетевые ошибки завершают цикл; timeout не доказывает отсутствие платы.
    Отказ означает неудачу подбора, а не доказательство отсутствия решения.
22. **Ручной сценарий не запускается автоматически.** CLI принимает ключ только
    из окружения, не читает `.env`, сохраняет лишь проверенный результат с demo_unverified
    и предупреждением, атомарно и без перезаписи по умолчанию. Код выхода отражает
    успех/ошибку. Тесты без настоящего ключа и сети.
23. **Ключ проверяется до HTTPX, а не маскируется в логах.** Разрешен печатный ASCII,
    внешние ASCII-пробелы удаляются; пустота, управляющие (также на краях), DEL и
    non-ASCII отвергаются безопасной ошибкой конфигурации до транспорта.
    HTTPcore DEBUG остается включаемым: h11 не получает недопустимый Authorization.
    Регрессия использует настоящий AsyncHTTPTransport/h11 с тестовым network backend.
24. **Сжатие ответов не поддерживается.** Явный `Accept-Encoding: identity`;
    Content-Encoding кроме отсутствующего/identity отвергается до чтения тела,
    byte-limit применяется к сырому aiter_raw, без декомпрессии HTTPX.
    Отказ и явная отмена закрывают поток; общий deadline и три вызова сохранены.
25. **Все CLI-результаты в generated/.** --output — относительный путь внутри
    выделенного игнорируемого каталога, также для вложенных имен и временных файлов.
    Абсолютные пути, .. и symlink запрещены. Linux/POSIX dir_fd и O_NOFOLLOW
    фиксируют каталог без следования symlink; права каталога 0700, файлов 0600.
    Атомарный link без --overwrite защищает от гонки создания результата,
    replace с явным разрешением заменяет готовый файл; ошибки записи очищают temporary.
26. **MEAL-3 — закрытый промежуточный HTTP-сценарий.** MEAL-2 уже слита в master
    (`31ac2d2`); MEAL-3 основана на этом master, без зависимости от неслитой ветки.
    В отличие от будущего публичного API из решения 15, синхронный POST доступен
    только разработчику, по умолчанию выключен. Отдельный серверный SecretStr
    `GENERATION_ACCESS_TOKEN`, сравнение через secrets.compare_digest до тела/JSON
    и провайдера; пустой/некорректный токен при включении — ошибка конфигурации.
    HTTPBearer описан в OpenAPI; токен не передается Flutter и не логируется.
27. **Один процесс, без очереди и новых систем.** Только Uvicorn workers=1;
    один слот на процесс, конкурентный запрос немедленно получает 429.
    Чистый ASGI middleware ограничивает тело 64 KiB до JSON-разбора, включая chunked.
    Захват слота без await, освобождение в finally, отмена закрывает stream.
    Lifespan переиспользует/закрывает один HTTPX-клиент; выключенный endpoint его
    не создает. Старые API работают без ключей, БД/Redis/очередей не добавлены.
28. **HTTP не расширяет бюджет генерации.** Прежний сервис и ядро, максимум три
    вызова и общий deadline; результат только после всех проверок, demo-маркировка
    сохранена. Стабильные коды ошибок: авторизация DeepSeek дает 503, не 401 клиента;
    непроверенный план и сырой ответ не возвращаются. Идемпотентности и сохранения
    меню пока нет; повторный POST может стоить денег. Disconnect не обещает отмену
    или отсутствие расходов. Публичные задания/квоты остаются отдельным будущим этапом.
29. **Путь защиты совпадает с router; endpoint отказывает без guard.** Исправлен P1:
    сравнение полного ASGI path пропускало guard при Uvicorn root_path. Guard и
    обработчики ошибок используют starlette._utils.get_route_path, как FastAPI,
    с границами префикса и накопленным root_path mounts. Внутренний API допускается
    при frozen-установке из uv.lock (Starlette 1.7.0 / FastAPI 0.143.0) и регрессиях;
    после обновления версий они обязательны, собственного replace/алгоритма нет.
    Endpoint требует серверное подтверждение всех проверок guard, привязанное
    идентичностью к текущему scope и удаляемое в finally. Оно не приходит из HTTP;
    без подтверждения — 401 без генерации, даже если HTTPBearer разобрал верный токен.
    Slash/307 не обходят guard; root_path поддерживается, а не запрещается.
30. **Настоящая сборка в корневом main.py, плоское размещение пакета.** Main содержит
    create_app(), lifespan, подключение HTTP и владение ресурсами; manage только
    запускает Uvicorn с одним worker. Пакет meal_budget расположен рядом в корне;
    адаптера, второго main.py и ручного изменения sys.path нет. Все импорты фабрики
    и Docker переведены на новую структуру; HTTP-контракты и бизнес-логика не меняются.
    Прямой запуск manage.py через .venv работает без PYTHONPATH также из другой cwd.
    Reload только при выключенной HTTP-генерации.
    Окружение устанавливается uv sync --frozen; системный Python не изменяется.
    Локальные настройки PyCharm хранятся в игнорируемой .idea без секретов;
     workspace.xml и глобальные настройки IDE не переписываются.
31. **Сбор не заменяется выдуманными фактами.** Официальные карточки 5ka.ru
    2026-10-13 вернули HTTP 403. Реальный снимок пуст; demo-ID сохранены в
    отдельном demo-каталоге и fixtures, без молчаливой смены упаковок. Цель 30–40 товаров и реальные
    анкеты на этапе MEAL-4 были заблокированы. Ограничения сайта не обходятся.
    В MEAL-5 импортирован отдельно предоставленный снимок; его ограничения — CATALOG.
32. **Происхождение отдельно по цене и КБЖУ.** Обязательны URL и timestamps
    с offset; цена имеет канал, тип, условия и подтвержденную географию либо null.
    Неподтвержденная Москва не подставляется из анкеты. Сохраняются demo_unverified
    и версия каталога в расчетах/генерации; это снимок, не живая корзина.
33. **Единые JSON-числа с MEAL-4.** GET, plan, grams/servings, КБЖУ и допуск
    больше не возвращают Decimal-строки. Это намеренное изменение сериализации
    клиента; денежная Decimal-арифметика и допустимость числовых строк ввода сохранены.
34. **Вода — единственное исключение ингредиентов.** Обычная питьевая вода
    разрешена в steps и не учитывается в корзине/КБЖУ. Остальные пищевые продукты
    требуют catalog ID. Промпт не гарантирует соответствие свободного текста:
    ручная проверка обязательна, regex как доказательство не используется.
35. **Оценка через прежнюю генерацию.** На этапе MEAL-4 шесть заготовок blocked без фиктивных
    бюджетов; положительные требуют ручной witness, невозможный случай — нижнюю
    границу покупки по каталогу. CLI имеет необязательный --report; автономная
    сводка без сети пишет только в generated/ с прежней защитой. Стоимость API
    не рассчитывается без тарифа, автоматических платных наборов нет.
    В MEAL-5 ordinary/weekly подготовлены по ручным witness, остальные четыре blocked.
36. **Demo доступно по умолчанию, без скрытого fallback.** data/products.json
    сохраняет прежние synthetic_demo-данные, реальный снимок — data/5ka-products.json.
    CATALOG_PATH выбирает один файл; пустота/повреждение явно выбранного реального
    каталога не подменяются demo. Оба результата сохраняют demo_unverified.
37. **Явный сценарий — проверяемая подготовка, не метка отчета.** CLI требует ready,
    совпадающие request/catalog_version и расчетное доказательство до провайдера.
    Неизвестные/blocked ID отвергаются независимо от каталога. Обычная генерация
    без --scenario сохраняется. Автономная сводка не публикует success для blocked.
38. **Общий preflight назначений, атомарность каждого файла.** Output/report
    лексически нормализуются без следования symlink и проверяются вместе до mkdir.
    Вложенность, равенство и существующие препятствия отвергаются до провайдера.
    Гарантии против внешних гонок и атомарной пары файлов не заявляются.
39. **Наблюдение не подтвержденная цена.** В MEAL-5 отображенное предложение
    кодируется price_type=displayed и single_package_without_card=null,
    не regular/true с предупреждением. Способ чтения и относительный возраст кеша
    хранятся отдельно в источниках; checked_at не считается обновлением цены,
    deprecated price_updated_at для таких наблюдений null. Существующие подтвержденные
    типы совместимы, схемы проверяют структуру, не истинность утверждений.
40. **Масса как продается без новых единиц.** state_basis=as_sold явно обозначает
    трактовку сборщика; значения dry/raw/cooked и арифметика не меняются.
    Это не подтверждение термообработки/пастеризации; правило передается в промпт.
    Кандидаты с мл/шт./весом/неясным выходом остаются отдельным нерасчетным справочником.
41. **Curated подготовка в examples, результаты в generated.** Синтетические анкеты
    и ручные witness отслеживаются, совпадают с существующим manifest и проверяются
    до ready. Witness не отправляется провайдеру. Допуск ±10% не расширяется,
    запас бюджета описывается от корзины целых упаковок. Это не медицинская
    рекомендация или сертификат достоверности импортированных данных.
42. **Компактный контекст без сокращения ассортимента.** MEAL-6 отделяет PromptProduct
    от Product: семь расчетных/кулинарных полей, без per-SKU provenance и legacy.
    Ограничения происхождения — один catalog_context, исходный каталог/API полные.
    Компактный JSON не вырезает схему/правила; witness и скрытый отбор не используются.
43. **Причины отклонения — локальная ограниченная диагностика.** Отдельный приемник
    сервиса включается CLI при --report; RunSummary хранит историю до успеха/ошибки,
    HTTP metadata не расширяется. До 20 нарушений / 12 KiB на попытку, счетчик до
    усечения и максимум три записи. Только известные коды, безопасные пути, числовые
    actual/границы; без raw/неудачного меню/анкеты/msg/input/ctx. Старую историю
    восстановить нельзя. Correction получает актуальные нарушения последней попытки.
    Сбор — best effort: обычный сбой не меняет результат и отключает сборщик только
    в текущей генерации; резервная запись available=false, счетчик/усечение null,
    без текста исключения. Отмена и завершение процесса не подавляются.
44. **Две причины сбоя CLI сохраняются отдельно.** GenerationError печатается до
    записи --report; при ошибке записи дополнительно выводится безопасное файловое
    сообщение. Код выхода 2 сохраняет прежний приоритет локальной ошибки над 1;
    исходный код генерации остается в stderr. Повторной генерации нет.
45. **MEAL-8: закрытые durable-задания, не публичный Flutter API.** POST/GET защищены
    существующим серверным Bearer и выключены вместе с HTTP-генерацией. Сервис
    генерации/ядро/синхронный контракт прежние; root_path, fail-closed подтверждение
    guard и 64 KiB до JSON сохранены. Токены установок и квоты — следующий этап.
    Идемпотентности нет: повторный POST создает новое потенциально платное задание.
46. **PostgreSQL вместо отдельного брокера.** По уточнению архитектуры серверная
    SQLite заменена PostgreSQL без параллельной production-поддержки двух БД.
    JobStore отделен от router; один psycopg 3 и ограниченный async pool (1–4
    соединения по умолчанию, до 16 ожидающих, конфигурируемый timeout).
    До четырех queued по умолчанию, один worker/процесс и общий слот с синхронным
    POST. Redis/Celery/аккаунтов нет; масштабирование workers/реплик не реализовано.
    Disconnect не отменяет принятое, пул и HTTPX принадлежат lifespan.
47. **Durable running до провайдера; никогда не повторять его при восстановлении.**
    Running → failed/interrupted после сбоя/штатной отмены; токены могли потратиться.
    Queued восстанавливаются только при той же версии каталога, иначе безопасный
    catalog_version_mismatch. Terminal-результат остается привязан исходной версии.
    Сбой сохранения не разрешает повтор генерации. Три вызова, общий deadline
    после извлечения из очереди, отсутствие сетевых retries и HTTPX lifespan прежние.
48. **Минимальное временное хранение и отдельные миграции.** UUID/состояние/UTC-время,
    анкета/версия/проверенный результат или безопасный код. Decimal в JSONB
    сохраняется точно строкой, id — UUID, времена — TIMESTAMPTZ.
    TTL от завершения (24 ч по умолчанию), удаление
    terminal-строки вместе с анкетой/результатом, GET после удаления — 404. Очистка
    не удаляет queued/running; GET проверяет TTL независимо от фонового интервала.
    DELETE не обещает немедленного физического стирания из MVCC/WAL/backup;
    права, TLS и шифрование — ответственность администратора; данные не логируются.
    Реальная yoyo-миграция запускается отдельной командой, не в lifespan. Rollback
    первой версии удаляет таблицу/данные; тестируется только на временной БД.
    Данные БД/результаты не входят в Git/образ; Compose сохраняет PostgreSQL volume.
49. **Транзакционные гарантии не равны exactly-once.** Admission — READ COMMITTED,
    advisory xact lock и count+INSERT; claim — атомарный UPDATE с FOR UPDATE SKIP
    LOCKED/RETURNING; completed+result — одна транзакция. Ошибки откатываются,
    cleanup фильтрует terminal-состояния. Во время DeepSeek нет захваченного
    соединения/транзакции. Процессный слот и startup-recovery требуют единственного
    процесса. Сбой после внешнего платного вызова до сохранения результата возможен,
    автоматического повтора нет, exactly-once не обещается. Исход COMMIT при потере
    соединения тоже может быть неопределенным; HTTP-ошибка не разрешает автоповтор POST.
50. **Независимая PostgreSQL-история вместо переписывания примененной SQLite.**
    Архив SQLite — migrations/archive_sqlite/; доступного оригинала нет, происхождение
    и побайтовая неизменность не подтверждены. Файл не реконструируется. Активная первая
    версия — migrations/postgresql/001_generation_jobs_postgresql.py. migrate_jobs
    читает только ее историю. Старые SQLite-файлы не удаляются/не читаются, переноса
    данных нет; новая БД не знает старые ID. Миграции запускаются явно до API;
    тесты/CI используют настоящую отдельную PostgreSQL, не пользовательскую БД.
51. **MEAL-9 — установка, не аккаунт человека.** Открытый POST installations выдаёт
    случайные UUID и opaque Bearer с 256 битами энтропии; хранится только SHA-256
    (UNIQUE/CHECK). Без телефона/email/IP/fingerprint, JWT и refresh. Секрет один раз,
    no-store, будущий Flutter хранит его в OS secure storage. Без секрета recovery нет;
    переустановка создаёт новую установку, если ОС не сохранила прежний секрет.
    Бессрочность токена пока осознанное ограничение: revoke/rotation API не реализованы.
52. **Разделение app/developer.** App POST/GET используют только installation Bearer,
    developer/sync — только прежний серверный Bearer. Отдельный флаг app по умолчанию
    false и требует http=true. Один существующий worker/слот/очередь/HTTPX, прежний
    сервис и правила ядра. SQL owner-фильтр до состояния/ошибки даёт одинаковый 404
    для чужого/неизвестного задания. Старые developer jobs не получают фиктивных owners;
    закрытый developer API сохраняет административный доступ и не входит в app-квоты.
53. **Идемпотентность ограничена жизнью job.** Один ASCII-ключ 1–64 `[A-Za-z0-9_-]`,
    UNIQUE(owner,key), SHA-256 нормализованного GenerationRequest без сырой копии.
    Defaults/JSON-порядок/Decimal-форма/множества ID незначимы, wishes значимы.
    Версия каталога не входит в fingerprint запроса: повтор находит исходный job,
    409 только при иной анкете. Повтор — прежнее подтверждение 202, а не новое admission;
    работает без worker. GET активного при аварии сохраняет 503 MEAL-8.
    Ключ в самой строке job: активные удерживают его, terminal — TTL (default 24 ч).
    После удаления тот же ключ — новое задание/квота, не вечная идемпотентность.
54. **Квоты — атомарный admission, не денежный лимит.** Общий advisory xact lock
    с developer queue admission, одна транзакция для дедупликации/лимитов/двух счётчиков/
    INSERT. Default 3 app jobs/установку и 30 global/UTC-сутки по часам PostgreSQL.
    Независимые от TTL счётчики не освобождаются ошибкой/restart/удалением задания.
    Повтор/rollback/отказ до принятия не списывает квоту. 429 и Retry-After до UTC-полуночи;
    queue limit прежний, Retry-After=1 для app. До трёх внешних вызовов на job, не exactly-once.
55. **Ограниченный закрытый пилот, не полная публичная abuse-защита.** Регистрация
    20/UTC-сутки, 200 всего под отдельным DB-lock; total cap ограничивает рост таблицы,
    автоматического удаления установок нет. Capacity 429 требует решения оператора,
    Retry-After=86400 не обещает освобождения. Установки не уникальные люди, регистрационный
    cap можно исчерпать. Новые установки не обходят global quota. Не встраивать общий
    registration secret в Flutter; нужны внешние access/rate/connection/time limits,
    HTTPS/redaction/наблюдаемость и отдельная политика revoke/retention перед публикацией.
56. **Аддитивная yoyo 002 и поддерживаемый откат.** Явная зависимость от 001,
    nullable owner/key/hash с CHECK для legacy jobs, независимые таблицы квот.
    apply отдельно от API. `rollback --steps 1` на текущей истории удаляет MEAL-9
    app-данные, сохраняя developer jobs; полный rollback как прежде удаляет всё.
    Только остановленная тестовая/выведенная БД: reapply не восстанавливает токены
    и не является допустимым способом обнулить рабочие квоты.
