# Каталог «Пятёрочки»: происхождение и обновление

## Импорт MEAL-5

В `data/5ka-products.json` импортированы **70 SKU** из предоставленного
`5ka-products-expanded.json` (`5ka-2026-10-14-web-v2`). Версия импорта —
**`5ka-2026-10-14-observed-v3`**, статус по-прежнему `demo_unverified`.
Это снимок прочитанных представлений официальных карточек, **не актуальная
московская корзина**, не подтвержденные кассовые цены и не проверка наличия.
Импорт не повторял веб-сбор и не сверял этикетки. Pydantic подтверждает структуру,
а не достоверность фактов. Историческая попытка MEAL-4 13 октября вернула HTTP 403;
новые входные данные собраны отдельно 14 октября без обхода ограничений.

Исходные файлы в `outputs` не изменены. Их SHA-256:

| Файл | SHA-256 |
| --- | --- |
| `5ka-products-expanded.json` | `d048363afa3d50cd94bd2759299f0bdf45469b99d9f11ed4ce5293fb9234816b` |
| `5ka-candidates.json` | `eb5c4a9f2eb56fb16b2018f4adf9a21729c734fc6417422e3f0a231976fe86d7` |
| `5ka-expanded-notes.md` | `f862b85f27fe39f7676f456a16885357bfeaba83dc192930c240cab4f70906cd` |

Полные ссылки на каждую карточку, ID сети, времена чтения цены и КБЖУ находятся
в provenance товара. Отдельный справочник `data/5ka-candidates.json` скопирован
без изменений: **79 кандидатов**, **70 недоступных карточек** (не собранные товары)
и 135 `source_observations`. Расчетные ID и кандидаты не пересекаются.

## Ограничения происхождения

- Регион, адрес доставки и магазин не выбраны: `region_confirmed=false`,
  `region=null`, `store=null`. Онлайн-каталог доставки не офлайн-касса.
- Веб-инструмент возвращал в том числе кешированные представления.
  `checked_at` — время чтения/сверки представления в сессии сбора, **не время
  обновления цены**. `web_cache_age` перенесен из справочника для всех 70 товаров:
  18 today, 26 yesterday, 9 «2 days ago», 2 «3 days ago», 1 «4 days ago»,
  9 «5 days ago», 2 «6 days ago», 3 last week. Эти относительные строки не
  превращаются в придуманный timestamp кеша; today тоже не гарантирует live-страницу.
- Единственная отображенная цена без видимого маркера карты/нескольких упаковок
  **не доказывает** возможность покупки одной упаковки без карты. Корзина и касса
  не проверялись, цена не гарантируется на весь октябрь или для конкретного адреса.
- КБЖУ перенесены из карточек сети; фото, состав на этикетке и лабораторные значения
  не сверены. Проверка 4/9/4 не доказывает точность и не служит поводом переписывать
  опубликованные значения. При противоречиях нужны источники, а не усреднение.
- `state` в исходном сборе частично обозначает «как продается»: cooked у
  слабосоленого филе не означает термообработку, raw у молочного продукта —
  непастеризованность. Граммы относятся к массе до дополнительной готовки;
  dry у круп/смесей — сухая масса. Выход готового блюда не вычисляется.

## Уточнение схемы и причины новой версии

Состав, ID, названия, `state`, цены, упаковки и КБЖУ всех 70 записей сохранены.
Исключений **из входного расчетного файла — 0**, численных исправлений — 0.
Версия изменена из-за исправления **семантики provenance**, не нового сбора:

| Поле | Импорт v3 | Причина |
| --- | --- | --- |
| `price.price_type` | `displayed` вместо `regular` | Наблюдаемая цена, ее обычный/акционный статус не подтвержден |
| `price.single_package_without_card` | `null` вместо `true` | Условия без карты неизвестны, не утверждаются как факт |
| price/nutrition `observation_method` | `web_tool` | Чтение представления через инструмент, не проверка кассы |
| price/nutrition `web_cache_age` | Строка из `source_observations` | Возраст кеша буквально, неизвестный оставался бы null |
| `state_basis` | `as_sold` | Классификация сборщика, не подтверждение физической обработки |
| deprecated `price_updated_at` | `null` | Время чтения нельзя выдавать за дату обновления цены |

Прежние записи схемы совместимы: `observation_method=unspecified`,
`web_cache_age=null`, `state_basis=physical_state` по умолчанию; существующие
regular/promotional требуют `single_package_without_card=true`. Displayed допускается
только для онлайн-наблюдения, с null и объяснением в conditions; false, неясная цена
или отсутствие объяснения не становятся активной записью. Это режим разработки с
неподтвержденными условиями, не выполнение строгого требования кассовой цены.
Промпт разъясняет эти поля; схема и промпт не удостоверяют факты источника.

справочник. Причины сохранены по каждому ID: отсутствующая/неоднозначная цена,
неполные/противоречивые КБЖУ, штуки, мл/л, весовая продажа, кости/хвосты/кожура,
неясная масса без заливки или база отдельного топпинга. Например картофель
`5ka_3193948`, яйца `5ka_4213682`, масло `5ka_21676`, фасоль `5ka_3415786`,
орех `5ka_3428420` остаются вне расчета. `reported_weight_g` — буквальное поле
карточки, не масса съедобной части и не коэффициент конвертации. Плотности, массы
яйца и выхода после очистки не добавлялись. Новых единиц нет.

## Выбор каталога и совместимость ID

По умолчанию `data/products.json` — прежние три синтетических demo-продукта
`oats`, `buckwheat`, `chicken`, версия `demo-meal-3-v1`; значения не менялись.
Тесты арифметики используют независимые `tests/fixtures/products.json`.
Реальный снимок выбирается **явно**:

```bash
CATALOG_PATH=data/5ka-products.json uv run --frozen python manage.py
```

Новые ID `5ka_<retailer_product_id>` не подменяют demo-ID. Старое demo-меню с
выбранным снимком получает 422 unknown_product_id. Автоматического fallback нет:
поврежденный/отсутствующий выбранный файл прерывает startup; пустой каталог допустим,
но генерация по нему дает catalog_unavailable и calls=0.

## Воспроизводимость и обновление

Из корня репозитория, на исходных файлах данного сбора:

```bash
uv run --frozen python -m tools.import_5ka_snapshot \
  --products /home/crew/Documents/Codex/2026-10-10/x20-2/outputs/5ka-products-expanded.json \
  --candidates /home/crew/Documents/Codex/2026-10-10/x20-2/outputs/5ka-candidates.json
uv run --frozen python -m tools.prepare_evaluation
```

Первая команда перезаписывает только два импортированных файла в data/, проверяет
исходную версию/схему, ID и неизменность численных фактов. Вторая проверяет
curated ordinary/weekly из examples/ и записывает существующий manifest только
после успешной проверки обоих witness. Сети, ключей и генерации в этих командах нет.

Будущее изменение состава/фактов требует новой версии, документированных источников
и повторной подготовки сценариев. Для подтверждения цены выбрать адрес/регион,
сверить упаковку и условия без карты разрешенным способом; при блокировке остановиться.
Не переносить старое время на новую проверку. Перезапустить API: hot reload данных нет.
Снимок не резервирует товары и не обещает сроки хранения; арифметические остатки
упаковок не означают безопасное хранение. Вода вне корзины, все остальные пищевые
добавки требуют product_id. Проверки и ручные планы — [EVALUATION](EVALUATION.md).
