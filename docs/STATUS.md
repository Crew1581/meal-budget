## Что реально реализовано

- FastAPI/Pydantic v2, create_app/lifespan, health, каталог и OpenAPI.
- Локальный JSON-каталог с тремя demo-продуктами, валидация при startup.
- `POST /v1/menu-calculations`: КБЖУ меню, целые упаковки, остатки и бюджет.
  Прежний HTTP-контракт и поведение сохранены.
- HTTPX Chat Completions `/chat/completions`, JSON Output, настраиваемые ключ,
  base URL, модель, thinking, effort, tokens, четыре HTTP timeout и размер ответа.
  Один переиспользуемый клиент, async context закрывает его при успехе/ошибке.
  HTTPX перенесен из dev в runtime без изменения версии, lock обновлен.
- `GeneratedPlan` с рецептами, ингредиентами, порциями, days/meals, steps и
  заявленным временем; технические лимиты и явное преобразование в запрос ядра.
- Проверка схемы/ссылок, точных days/meals, исключений, бюджета по упаковкам,
  ежедневных диапазонов КБЖУ по неокругленным данным и заявленного времени.
  Нелюбимые продукты — предупреждение. Бюджет только из исходного запроса.
- Одна исходная генерация + до двух исправлений, полный recheck;
  общий deadline, ограниченный JSON-контекст исправления, без скрытых сетевых
  повторов, redirect или выдачи сырых ошибок. Непроверенный план не возвращается.
- Безопасные типизированные ошибки и метаданные: начатые вызовы, длительность,
  фактическая модель и известные поля token usage при наличии; без расчета тарифа.
- CLI `python -m meal_budget.generate_menu`: JSON-анкета, каталог, ключ только
  из окружения, атомарное сохранение только в игнорируемом `generated/`
  с правами 0600 без замены по умолчанию,
  коды выхода; пример анкеты и команды в README.
- Автономные тесты через HTTPX MockTransport, включая CLI и пример из README;
  критическая регрессия заголовка через настоящий AsyncHTTPTransport/httpcore/h11
  с подмененным network backend, без внешней сети.
- Обновлены .env.example, README, ARCHITECTURE, API, DECISIONS и ROADMAP.
- `POST /v1/menu-generations`: текущая GenerationRequest, ожидание прежнего сервиса,
  проверенный GenerationResult с расчетами и метаданными, без сырого ответа.
- По умолчанию `GENERATION_HTTP_ENABLED=false`: 404, нет маршрута в OpenAPI и
  HTTPX-клиента DeepSeek. Включение без корректного непустого access token
  отвергается в create_app безопасной ошибкой конфигурации.
- Отдельный SecretStr `GENERATION_ACCESS_TOKEN`, Bearer через compare_digest
  до тела/JSON/провайдера; OpenAPI показывает HTTP Bearer. Не токен Flutter.
- ASGI guard: один слот на процесс, немедленный 429 без очереди, тело до
  65536 байт до JSON-разбора, включая chunked и недостоверную Content-Length.
  Слот освобождается в finally после успеха, ошибки, отмены и отказа по телу.
- Один общий provider/HTTPX-клиент в lifespan; shutdown закрывает клиент,
  отмена генерации закрывает поток, не ломая клиент для следующего запроса.
- Стабильные безопасные HTTP-коды: 401 доступа, 413 размера, 422 анкеты/исчерпания
  попыток, 429 слота, 504 timeout, 503 недоступности/лимита/авторизации DeepSeek,
  502 невалидного ответа. Глубокий JSON тоже дает 422, без input или меню в ошибке.
- Пример локального запуска с workers=1 и curl без retries, серверным ключом,
  отдельным токеном через stdin и результатом внутри generated/ — в README.

## Исправление P1: ASGI root_path

Дефект: guard сравнивал полный scope.path с каноническим путем, а router снимал
root_path. При `uvicorn --root-path /api` запрос доходил до endpoint без авторизации,
лимита тела и слота; обработчики ошибок тоже неверно сопоставляли путь.
HTTPBearer(auto_error=False) не проверяет секрет и не был резервной защитой.

Исправление: guard и обработчики ошибок генерации/расчета используют
starlette._utils.get_route_path, как router текущих Starlette 1.7.0 / FastAPI 0.143.0
(версии в uv.lock). Учитываются граница префикса, его полное вложенное значение,
отсутствие префикса в path и накопленный root_path mounts; нет наивного replace.
Внутренний API — явная зависимость, его поведение закреплено регрессиями;
обновление фреймворка требует их повторного запуска.

После всех проверок guard создает в приватном поле scope подтверждение,
привязанное идентичностью к этому объекту scope; оно удаляется в finally.
Endpoint без такого подтверждения возвращает безопасный 401 без провайдера,
включая случай верного Bearer, bool вместо подтверждения и другой scope.
Клиент не может передать подтверждение через HTTP headers или JSON.
Compare_digest сохранен, non-ASCII Authorization безопасно отвергается.
Slash защищен до router; 307 не вызывает генерацию, канонический POST проверяется заново.

## Сохраненные защитные свойства MEAL-2

1. **Утечка ключа через HTTPcore DEBUG.** До HTTPX удаляются внешние ASCII-пробелы;
   пустой ключ, управляющие символы (включая края), DEL и non-ASCII отвергаются
   безопасной ошибкой конфигурации. Исходное значение в ошибку не включается,
   логирование не отключается. Тесты `tests/test_deepseek_headers.py` проверяют
   реальную h11-сериализацию нормализованного Authorization, наличие DEBUG-событий,
   отсутствие секрета и ноль обращений к transport/backend для некорректных ключей.
2. **Распаковка до ограничения памяти.** Отправляется `Accept-Encoding: identity`;
   другое Content-Encoding отвергается до чтения тела, лимит применяется к aiter_raw.
   Тесты доказывают ноль чтений gzip-потока и отсутствие вызова декодера,
   закрытие при отказе, успех несжатого/identity ответа и остановку на byte-limit.
   Порог peak memory не используется как доказательство.
3. **Результаты CLI могли попасть в Git.** --output теперь только относительный
   путь внутри generated/. Абсолютные пути, .., symlink корня/родителей/файла
   запрещены; обход и запись через dir_fd/O_NOFOLLOW. Временные файлы тоже внутри
   generated/, Git игнорирует весь каталог, но не JSON каталога/примеров.
   Тестируются вложенный результат, размещение temporary, права, запреты путей,
   symlink с/без --overwrite и `git check-ignore --no-index` для разных имен.
4. **P3: импорт без файловых возможностей.** Флаги вычисляются только после
   проверки Linux и наличия O_DIRECTORY/O_NOFOLLOW. Неподдерживаемая платформа
   получает понятное сообщение и код 2 до файловых операций и провайдера,
   без traceback; импорт и --help доступны. README/help явно ограничивают
   файловый сценарий Linux; небезопасного fallback и переноса на Windows нет.
   Регрессии в отдельном процессе покрывают отсутствие каждого/обоих флагов,
   win32/darwin, обычный запуск через MockTransport и --help.

Дополнительные регрессии: явная отмена закрывает поток и клиент; ошибка записи
не оставляет partial/temporary и сохраняет прежний результат; гонка между проверкой
и атомарным link не перезаписывает чужой файл. Новые проверки отмены/записи/гонки
синхронизируются Event или подменой операции, без временных порогов и sleep.
Dockerfile создает /app/generated с правами 0700 для UID 10001; CLI работает
в контейнере без записи в произвольный каталог. Новых зависимостей не добавлено.

## Ограничения и настройки

По официальной документации 2026-10-11 пример экономичной модели — `deepseek-flash`
(DeepSeek-V4.1-Flash), JSON Output и thinking поддерживаются. Модель остается
конфигурацией; в Settings имя по умолчанию пустое. Thinking явно `disabled`,
при `enabled` effort по умолчанию `low`; `omit` для модели без параметра thinking.
По умолчанию: 8192 output tokens на вызов, 262144 байта полного ответа,
180 секунд на весь цикл, КБЖУ ±10% каждого показателя каждого дня включительно.
Допуск — продуктовая настройка, не медицинская норма; ограничения не ослабляются.

Деньги — Decimal; покупки с нуля целыми упаковками. Состояния dry/raw/cooked
не пересчитываются. Каталог и результат `demo_unverified`: цены/КБЖУ не проверены
для реального питания. Не проверяются реальное время приготовления, безопасность
инструкций и медицинская полноценность. Промпт не заменяет серверную верификацию.
HTTP endpoint только закрытый, для разработчика, по умолчанию выключен.
Только один процесс Uvicorn / workers=1, без reload и нескольких реплик;
локальный слот не обеспечивает распределенные лимиты. Общий deadline сервиса
не ограничивает время загрузки тела. Идемпотентности нет: повторный POST — новая
потенциально платная генерация (до трех вызовов). Disconnect не гарантирует отмену
задачи или отсутствие расходов; слот может оставаться занятым до результата/deadline.
Нет заданий, серверного сохранения меню, БД, Redis, очередей, миграций, токенов
установок, Flutter, оптимизатора или поиска магазинов. Старые API работают без ключей.
