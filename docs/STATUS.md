# Текущий статус

## Текущий этап

Детерминированный расчет вручную подготовленного меню и сохранение контекста:
реализация готова, ревью MEAL-1 пройдено без блокирующих замечаний.
Публикация пока не выполнена: глобальные инструкции агента запрещают push.

## Что реально реализовано

- FastAPI/Pydantic v2, create_app/lifespan, health, каталог, OpenAPI и документация.
- Локальный JSON-каталог с тремя демонстрационными продуктами, проверка при startup.
- Схема будущего запроса генерации, без endpoint генерации.
- Независимый от FastAPI service и `POST /v1/menu-calculations`: КБЖУ приемов
  пищи, дней и периода; общая потребность, целые упаковки, остатки и бюджет.
- Валидация структуры, технических лимитов и ссылок; безопасный формат HTTP 422.
- Unit/API-тесты с отдельным простым каталогом; пример в examples/.

## Ключевые ограничения и решения

Деньги — Decimal в рублях. Расчет — локальный контекст 80 цифр, общий знаменатель
порций при агрегации, ROUND_HALF_UP до двух знаков только на выводе.
Все продукты покупаются с нуля; запасы и готовые остатки не учитываются.
Состояния dry/raw/cooked не пересчитываются. Цены и КБЖУ — только из каталога.
Превышение бюджета — HTTP 200, без изменения меню. Каталог demo_unverified,
не пригоден для реального планирования питания.
Flutter и локальная SQLite запланированы. Аккаунтов, серверной БД, миграций,
DeepSeek, генерации, оптимизации и фоновых заданий нет.
Будущие серверные миграции — yoyo, не Alembic; сейчас зависимость не установлена.
Долгосрочный план — ROADMAP, архитектурные решения — DECISIONS.
