**Подготовлены инфраструктура и шесть заготовок, не готовые анкеты.**
`examples/evaluation/scenarios.json`: ordinary, weekly, preferences, quick,
tight-budget, impossible. Все blocked, request/witness=null. Нет выдуманных
бюджетов и КБЖУ. Положительные свидетельства по реальным товарам и доказательство
невозможности по каталогу пока не подготовлены: требуют доступного непустого каталога.

Есть схемы готовности, автономная сводка, шаблон ручной оценки, порядок подготовки
и команда одного будущего запуска в [EVALUATION](EVALUATION.md).
Явный --scenario теперь требует существующий ready ID, подготовленные request,
catalog_version и witness/нижнюю границу покупки. Положительное свидетельство
проверяется ядром, анкета/версия должны совпадать; нижняя граница сверяется по
товарам после исключений. Blocked/неизвестные ID отвергаются до провайдера
независимо от каталога, с понятным сообщением и кодом 2, без success-report.
Без --scenario обычная генерация доступна и не зависит от manifest.
Механизм проверки положительного witness протестирован на **синтетической fixture**
тем же расчетным ядром; это не доказательство реального сценария питания.

## Реализованная техническая часть MEAL-4

- Происхождение Product: сеть, официальная карточка, опубликованный ID либо null,
  отдельные price/nutrition URL и AwareDatetime; канал, тип и условия цены,
  опубликованный период, подтвержденный регион/магазин либо null.
  Неясная цена не допускается в активной записи; схемы не доказывают факты страницы.
- catalog_version обязателен в каталоге, расчетах, генерации и сводке;
  версии generation/calculation проверяются на совпадение.
- Единый выход JSON-чисел: граммы, порции, КБЖУ, допуск и деньги. Decimal внутри,
  float только на границе JSON, финансовая арифметика не менялась.
  Добавлен структурированный provenance; прежние общие поля сохранены как
  deprecated производные (неподтвержденные регион/дата — null);
  изменения клиентского контракта описаны в API.
- Вода в steps вне ingredients/корзины/КБЖУ; все остальные пищевые добавки
  требуют ingredients с product_id. Правило в промпте, ручная сверка обязательна;
  автоматическое полное соответствие свободного текста не обещается.
- Пустой каталог допустим при startup. Генерация останавливается с
  catalog_unavailable, HTTP 503 и calls=0 до проверки/вызова провайдера.
- Прежний CLI получил необязательные --scenario/--report, без второго сервиса;
  успех/ошибка, модель/режим, calls/длительность/usage и ручная оценка.
  `evaluate_menu` — автономная сводка без сети и чтения .env.
  Все выходы через прежний защищенный generated/, без symlink/.. и замены по умолчанию.
- Общая проверка output/report идет до создания родителей: лексическая нормализация
  без resolve, запрет равенства/вложенности и существующих препятствий/неподходящих
  прав. Корректные соседние пути и общие родители поддерживаются. Внешние гонки не
  устранены; каждый файл публикуется атомарно отдельно, пара файлов не атомарна.
- Автономная сводка не публикует outcome=success для blocked-сценария;
  сводка без результата относится к реальному снимку, не подменяет его demo.
- Документация актуализирована; Docker включает только curated manifest сценариев,
  не tests, секреты или результаты. Новых зависимостей/БД/миграций/админки нет.

## Сохраненные возможности и ограничения

FastAPI/Pydantic v2, корневые main.py/create_app/lifespan и manage.py;
health, products, расчет целых упаковок и независимая проверка генерации.
Закрытый HTTP endpoint выключен по умолчанию; отдельный Bearer до тела,
64 KiB, один слот/процесс, root_path-защита и fail closed без guard.
Workers=1, без reload при HTTP-генерации; до трех вызовов и общий deadline,
без сетевых retries/redirect; HTTPX-клиент принадлежит lifespan/CLI.
Защита заголовков от утечки, raw byte-limit без распаковки и Linux O_NOFOLLOW
сохранены. Disconnect не гарантирует отмену или отсутствие расходов.

Нет живой корзины/наличия, публичных заданий/квот/идемпотентности, аккаунтов,
Flutter, БД или оптимизатора. Единицы только граммы; нет неявной плотности,
массы яйца, весовых упаковок или съедобного выхода. Время приготовления только
заявленное; безопасность, реалистичность порций и медицинская полноценность
не доказаны сервером. Synthetic fixtures не реальный каталог сети.
